# 单题模拟回答评分规格 v0.1

## 1. 目标

本规格定义“单题模拟回答评分”的产品和 Agent 输出标准。

该功能用于完整面试备战包生成之后。用户从岗位专属面试题库中选择一道题，输入自己的回答，系统对回答进行评分、指出问题、生成改进版回答，并给出下一题训练建议。

## 2. 使用场景

典型流程：

```text
用户生成完整面试备战包
↓
用户选择一道面试题
↓
用户输入自己的回答
↓
系统基于题目、JD、简历、题目高分框架进行评分
↓
系统输出优点、问题、改进版回答和追问
↓
系统记录薄弱点，用于下一轮题目推荐
```

## 3. 输入

必需输入：

1. 题目：来自岗位专属面试题库，或用户手动输入。
2. 用户回答：用户对该题的文本回答。
3. 目标岗位 JD：用于判断回答是否贴合岗位要求。
4. 用户简历：用于判断回答是否结合真实项目和经历。

推荐输入：

1. 题目的高分回答框架。
2. 题目的 JD 匹配关键词。
3. 题目的来源依据。
4. 用户历史薄弱点。
5. 当前题目所属模块：自我介绍、专业能力、行为经历与项目深挖。

## 4. 输出

单题评分报告需要包含：

1. 总分：100 分制。
2. 分项评分。
3. 总体评价。
4. 表现好的地方。
5. 需要改进的地方。
6. 技术错误或表达风险。
7. 高分回答框架。
8. 改进版回答。
9. 可能的面试官追问。
10. 下一题练习建议。
11. 记忆更新建议。

## 5. 评分维度

### 5.1 相关性，20 分

判断用户是否回答了题目本身。

扣分情况：

1. 回答偏题。
2. 只讲项目背景，没有回应问题核心。
3. 用通用话术绕开技术细节。

### 5.2 技术准确性，25 分

判断技术概念、方案描述和因果关系是否正确。

扣分情况：

1. 技术概念错误。
2. 把不相关的技术强行关联。
3. 对数据库、缓存、并发、网络等后端基础解释错误。
4. 方案不可落地。

### 5.3 项目具体性，20 分

判断回答是否结合用户简历中的真实项目。

扣分情况：

1. 没有提到项目中的具体场景。
2. 没有说明个人职责。
3. 没有说明技术方案、难点或结果。
4. 使用了简历中没有出现的经历但没有说明来源。

### 5.4 结构性，15 分

判断回答是否有清晰逻辑。

推荐结构：

1. 结论先行。
2. 背景说明。
3. 个人行动。
4. 技术细节。
5. 结果和复盘。

扣分情况：

1. 顺序混乱。
2. 没有重点。
3. 只堆技术名词。
4. 说了很多但没有结论。

### 5.5 表达力，10 分

判断回答是否简洁、自然、适合面试现场表达。

扣分情况：

1. 句子过长。
2. 口语化严重但没有信息量。
3. 过度背书面概念。
4. 不能在 1 到 3 分钟内讲清楚。

### 5.6 风险控制，10 分

判断回答是否存在面试风险。

风险包括：

1. 夸大个人贡献。
2. 暴露明显不熟悉的技术。
3. 说法前后矛盾。
4. 编造简历中没有的经历。
5. 对不确定内容说得过于绝对。

## 6. 输出格式

推荐结构：

```text
总分：82 / 100

分项评分：
1. 相关性：18 / 20
2. 技术准确性：20 / 25
3. 项目具体性：15 / 20
4. 结构性：12 / 15
5. 表达力：8 / 10
6. 风险控制：9 / 10

总体评价：
你的回答方向正确，但项目细节和技术决策理由还不够具体。

表现好的地方：
1. 能说明项目背景。
2. 能说清楚自己负责的模块。

需要改进的地方：
1. 没有解释为什么选择该技术方案。
2. 没有用数据说明结果。

技术错误或表达风险：
1. “这个功能都是我一个人完成的”容易被认为夸大贡献。

改进版回答：
...

可能追问：
1. 如果数据量扩大 10 倍，你会怎么优化？
2. 你怎么验证这个优化真的有效？

下一题建议：
建议下一题练习数据库索引和接口性能优化相关问题。
```

## 7. 改进版回答生成原则

改进版回答需要遵守：

1. 只能使用用户简历、回答、JD 中已有的信息。
2. 不编造用户没有做过的项目和结果。
3. 如果需要补充数据，需要标注为“可补充数据”，不能直接当作事实。
4. 优先使用 STAR 结构。
5. 保持面试现场可说出口的自然表达。
6. 回答不宜过长，普通问题建议控制在 1 到 2 分钟表达量。

## 8. 追问生成原则

追问需要模拟真实面试官的连续追问。

优先追问：

1. 用户回答中最模糊的地方。
2. 用户简历中和当前问题相关的项目细节。
3. JD 中强调但用户没有讲清楚的能力。
4. 用户回答中可能存在风险的表述。

追问不应：

1. 跳到完全无关技术领域。
2. 追问用户简历中没有任何依据的经历。
3. 连续问过多问题导致练习不可执行。

## 9. 记忆更新规则

单题评分后，系统需要判断是否更新用户长期记忆。

可以写入长期记忆的内容：

1. 多次出现的技术薄弱点。
2. 多次出现的表达问题。
3. 用户明显擅长的能力。
4. 用户常被追问但回答不好的项目。

不应写入长期记忆的内容：

1. 单次偶然失误。
2. 未经用户确认的敏感个人信息。
3. 模型推断但证据不足的结论。

记忆更新示例：

```json
{
  "weaknesses": [
    {
      "type": "technical",
      "topic": "MySQL 索引优化",
      "evidence": "在两次回答中无法说明索引生效判断方式",
      "confidence": 0.82
    }
  ],
  "next_training_focus": ["数据库索引", "接口性能优化"]
}
```

## 10. 质量验收标准

单题评分输出需要满足：

1. 必须有总分和分项分数。
2. 必须解释扣分原因。
3. 必须指出至少 1 条具体改进建议。
4. 改进版回答不能编造用户经历。
5. 至少生成 1 个合理追问。
6. 必须给出下一题练习方向。
7. 如果回答材料不足，需要明确提示用户补充信息。
