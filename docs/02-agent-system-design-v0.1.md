# AI Interview Coach Agent 系统设计 v0.1

## 1. 设计目标

系统设计目标不是“把一个大 prompt 扔给模型”，而是将求职准备任务拆成可调度、可记录、可评测、可迭代的 Agent 工作流。

核心设计目标：

1. Harness 层统一管理 Agent 调度、状态、记忆、工具调用和结果校验。
2. 多 Agent 分工完成简历解析、JD 解析、面经归纳、匹配分析、题库生成、回答评分、复盘总结。
3. 所有关键中间结果尽量结构化，便于校验、存储和评测。
4. 输出必须可追溯到用户输入材料，减少编造和泛化。
5. 系统能够根据用户反馈和历史表现优化后续训练策略。

## 2. 总体架构

```text
用户界面 / API 层
↓
Harness 编排层
↓
Agent 协作层
↓
工具层
↓
数据与记忆层
↓
评测与日志层
```

## 3. Harness 编排层

Harness 是整个系统的控制中心。

主要职责：

1. Workflow 管理：定义一次任务从输入到输出的执行步骤。
2. Agent 调度：决定当前步骤由哪个 Agent 执行。
3. 状态管理：维护当前任务的上下文状态。
4. 记忆管理：读取和写入用户长期记忆。
5. 工具调用管理：统一调用文件解析、检索、报告生成等工具。
6. 输出校验：检查 Agent 输出是否满足 schema。
7. 异常处理：失败重试、降级输出、错误记录。
8. 审计日志：记录每个 Agent 的输入、输出、耗时和工具调用。

Harness 不直接负责生成最终内容，而是负责任务拆解和质量控制。

## 4. Agent 分工

### 4.1 Document Parser Agent

职责：

1. 识别输入文件类型。
2. 从 PDF、DOCX、Markdown、纯文本中提取正文。
3. 将面试录音转写文本识别为复盘材料。
4. 输出标准化文本和文档元信息。

### 4.2 Resume Analyzer Agent

职责：

1. 解析简历结构。
2. 提取教育背景、技能、项目、实习、工作经历。
3. 标注后端开发相关能力。
4. 识别简历亮点和表达不足。

输出：ResumeProfile。

### 4.3 JD Analyzer Agent

职责：

1. 提取岗位名称和岗位方向。
2. 拆解岗位职责。
3. 提取硬性要求、加分项和技术关键词。
4. 识别后端岗位能力模型中的匹配维度。

输出：JDProfile。

### 4.4 Interview Experience Analyzer Agent

职责：

1. 处理用户手动粘贴的面经。
2. 提取高频问题。
3. 提取高频知识点。
4. 识别与目标 JD 和用户简历相关的内容。

输出：ExperienceProfile。

### 4.5 Matching Agent

职责：

1. 对比 ResumeProfile 和 JDProfile。
2. 生成匹配度。
3. 输出优势、短板、风险点。
4. 生成简历修改建议。
5. 为题库生成提供重点方向。

输出：MatchReport。

### 4.6 Question Bank Agent

职责：

1. 生成岗位专属面试题库。
2. 保证总题量不少于 25 道。
3. 保证三个模块每个不少于 8 道。
4. 为每道题生成高分回答框架和 STAR 模板。
5. 为行为经历和项目题生成 1 到 2 个追问。

输出：QuestionBank。

### 4.7 Prep Manual Agent

职责：

1. 生成面试备战要点手册。
2. 输出不少于 8 条回答加分点。
3. 输出不少于 6 条回答雷点。
4. 生成简历细节匹配、现场话术节奏、反问环节话术建议。

输出：PrepManual。

### 4.8 Answer Evaluator Agent

职责：

1. 对用户回答进行评分。
2. 分析回答是否相关、准确、结构清晰、具体、有项目细节。
3. 识别技术错误、表达风险和夸大风险。
4. 给出改进建议和参考回答。

输出：AnswerEvaluation。

### 4.9 Interview Review Agent

职责：

1. 分析真实面试转写文本或面试回忆。
2. 提取面试问题和用户回答。
3. 判断表现好和表现差的部分。
4. 总结薄弱点。
5. 生成下一轮训练计划。

输出：InterviewReviewReport。

### 4.10 Memory Agent

职责：

1. 维护用户长期画像。
2. 记录用户常投岗位、常用简历项目、薄弱知识点、表达习惯。
3. 将历史反馈用于下一次题库生成和评分。
4. 避免把单次偶然表现误判为长期问题。

输出：UserMemoryUpdate。

## 5. 关键工作流

### 5.1 生成面试备战包

```text
输入：简历 + JD + 可选面经
↓
Document Parser Agent 提取文本
↓
Resume Analyzer Agent 生成 ResumeProfile
↓
JD Analyzer Agent 生成 JDProfile
↓
Interview Experience Analyzer Agent 生成 ExperienceProfile
↓
Matching Agent 生成 MatchReport
↓
Question Bank Agent 生成 QuestionBank
↓
Prep Manual Agent 生成 PrepManual
↓
Harness 汇总为 InterviewPrepPackage，并为每道题保留 question_id、来源依据和评分锚点
↓
评测与日志层记录质量指标
```

### 5.2 单题模拟练习

```text
输入：题目 + 用户回答 + ResumeProfile + JDProfile + 题目评分锚点
↓
Answer Evaluator Agent 评分
↓
Answer Evaluator Agent 生成扣分原因、改进版回答和追问
↓
Memory Agent 更新薄弱点
↓
输出：评分、优点、问题、改进版回答、下一题建议
```

单题模拟练习是第一版 MVP 的核心工作流之一，需要和完整面试备战包生成同时支持。

### 5.3 真实面试复盘

```text
输入：面试录音转写文本或面试回忆
↓
Document Parser Agent 清洗文本
↓
Interview Review Agent 抽取问题与回答
↓
Answer Evaluator Agent 对关键回答评分
↓
Memory Agent 归纳长期薄弱点
↓
输出：复盘报告和下一轮训练计划
```

## 6. 结构化数据对象

### 6.1 ResumeProfile

包含：

1. 基本信息。
2. 教育背景。
3. 技术技能。
4. 项目经历。
5. 实习或工作经历。
6. 后端能力标签。
7. 可追问点。
8. 表达风险点。

### 6.2 JDProfile

包含：

1. 岗位名称。
2. 岗位级别。
3. 核心职责。
4. 硬性要求。
5. 加分项。
6. 技术关键词。
7. 后端能力维度。
8. 面试可能考察方向。

### 6.3 ExperienceProfile

包含：

1. 面经来源说明。
2. 高频问题。
3. 高频知识点。
4. 高频追问。
5. 与 JD 的关联点。
6. 与简历项目的关联点。

### 6.4 MatchReport

包含：

1. 总体匹配度。
2. 匹配优势。
3. 缺失能力。
4. 表达不足。
5. 简历优化建议。
6. 面试准备优先级。
7. 证据引用。

### 6.5 QuestionBank

包含：

1. 自我介绍定制题。
2. 后端岗位专业能力题。
3. 行为经历与项目深挖题。
4. 每题的高分回答框架。
5. 每题的 STAR 模板。
6. 每题的来源依据。
7. 每题的 JD 匹配关键词。

### 6.6 PrepManual

包含：

1. 回答加分点。
2. 回答雷点。
3. 简历细节匹配建议。
4. 现场话术节奏建议。
5. 反问环节话术建议。

### 6.7 AnswerEvaluation

包含：

1. question_id。
2. 用户原始回答。
3. 总分。
4. 分项评分：相关性、技术准确性、项目具体性、结构性、表达力、风险控制。
5. 表现好的地方。
6. 需要改进的地方。
7. 技术错误或表达风险。
8. 改进版回答。
9. 可能追问。
10. 下一题练习建议。
11. 记忆更新建议。

## 7. 记忆设计

### 7.1 会话记忆

用于保存当前一次任务的上下文，例如当前简历、当前 JD、当前题库、当前回答。

### 7.2 用户长期记忆

用于保存跨任务积累的信息：

1. 常投岗位。
2. 常用项目。
3. 高频薄弱点。
4. 表达习惯。
5. 历史训练得分。
6. 用户采纳过的建议。

### 7.3 材料记忆

用于保存用户上传或粘贴过的材料：

1. 简历版本。
2. JD 记录。
3. 面经记录。
4. 面试复盘记录。

## 8. 评测设计

### 8.1 输出格式评测

检查：

1. 是否输出完整字段。
2. 题量是否达标。
3. 每个模块数量是否达标。
4. 是否包含高分回答框架和 STAR 模板。
5. 是否包含来源依据。
6. 单题评分是否包含总分、分项分数、扣分原因、改进版回答和下一题建议。

### 8.2 内容质量评测

检查：

1. 专业能力题是否紧扣 JD。
2. 项目题是否来自用户真实简历。
3. 追问是否合理。
4. 建议是否可执行。
5. 是否存在编造用户经历的问题。
6. 单题评分是否能定位到用户回答中的具体问题。
7. 改进版回答是否保留用户真实经历，不虚构项目结果。

### 8.3 用户价值评测

检查：

1. 用户是否采纳简历建议。
2. 用户是否收藏或练习某些题目。
3. 用户同类问题多轮练习得分是否提升。
4. 用户是否认为报告有帮助。

### 8.4 自进化评测

检查：

1. 加入用户反馈后，下一轮题目是否更贴合薄弱点。
2. Prompt 版本更新后，评测集得分是否提升。
3. 长期记忆是否能减少重复泛化建议。

## 9. 安全与边界

系统需要遵守以下边界：

1. 不编造用户没有做过的项目经历。
2. 不建议用户虚构工作经验或学历。
3. 不把面经当作确定真题，只能标注为参考材料。
4. 不在第一版自动联网搜索面经。
5. 对简历、面经、面试记录等敏感信息做本地化存储和最小化展示。

## 10. 当前系统设计结论

第一版的系统重点不是复杂前端，而是：

1. 把用户材料解析成结构化数据。
2. 用 Harness 编排多个 Agent。
3. 生成有证据、有结构、可评测的完整面试备战包。
4. 支持用户基于题库进行单题模拟回答评分。
5. 对用户回答和真实面试复盘进行量化评价。
6. 通过记忆和反馈形成持续改进闭环。
