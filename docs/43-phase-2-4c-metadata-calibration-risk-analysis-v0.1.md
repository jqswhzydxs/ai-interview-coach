# Phase 2.4C Risk Analysis

| 风险 | 控制与验证 |
| --- | --- |
| 改写 run2 或冻结资产 | 输出目录必须与源目录分离；执行期间禁止向源树写入；全文件哈希前后比对 |
| 模型链路意外改变 | 新 assembler 独立，现有 Agent/client/Prompt/Schema/默认服务只读；没有 Provider 调用入口 |
| 固定模板加回显伪装为语义改进 | 按意图与多个主题生成可检查知识点；字段多样性仅描述；最终交给新的独立盲评 |
| 把缺口或建议说成真实经历 | 字段路径 provenance、原值 quote、inferred 类型；不预填项目行动/结果；缺材料显式说明 |
| 错误附加不相关来源 | 每题按显式技术词/主题/项目名称选源；没有相关证据时用问句推导的 inferred 来源 |
| 未知框架注入固定技术 | 规则使用通用机制，仅引用问句和当前 Resume/JD 内的技术；完整输出检查，而非只看正文 |
| 敏感内容或输入指令反射 | 只遍历白名单结构化字段；秘密/指令模式拒绝或丢弃；不保存原始文档/凭证 |
| 简单关键词误判、否定语义和新主题 | 词边界、否定约束处理和保守 fallback；独立语言/技术栈 holdout；规则局限由评审报告公开 |
| 对 375 题过拟合 | 不按 submission/题号选规则；先冻结独立 authored holdout，测试稀疏证据、角色迁移与新技术栈 |
| 盲评泄漏 | 新 opaque ID、全局随机顺序，包中无版本/旧 ID/哈希指纹/映射；映射隔离在 audit；评审须只读指定包 |
| 复用旧评分造成虚假提升 | 旧分仅用于误差分析；新模板全为空；工程报告不给 metadata_fit 新分数 |
| 自动验证被误解为质量通过 | 明确 structural_pass 与 semantic_review_pending；不晋升，不宣称达到 3.5 |

确定性代码无法证明任意自然语言的完整语义正确性。支持范围内的意图/主题规则
通过自动测试，范围外使用保守的问句约束说明。所有语义与 source 适配度仍须
独立评审，包括规则遗漏、模糊问句和中英文混合场景。
