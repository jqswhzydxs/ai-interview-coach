# 后续改进与优化清单 v0.1

## 1. 目的

这份文档专门记录第一版暂不做，但后续可以增强项目技术含量、产品完整度和简历展示效果的方向。

第一版要保持克制，先完成核心闭环。下面内容不进入 MVP，除非后续明确调整范围。

## 2. 产品能力优化

### 2.1 前端 Web 界面

后续可以增加：

1. 简历上传页面。
2. JD 粘贴页面。
3. 备战包报告页面。
4. 题库练习页面。
5. 历史评分趋势页面。

技术建议：

1. Next.js 或 React。
2. 报告页面支持目录导航。
3. 题库支持模块、难度筛选。
4. 单题评分支持对比多次回答。

### 2.2 登录注册与多用户

后续可以增加：

1. 用户注册登录。
2. JWT 鉴权。
3. 多用户数据隔离。
4. 用户个人中心。
5. 简历版本管理。

### 2.3 真实面试转写复盘

第一版只处理单题评分，真实面试复盘后置。

后续可以增加：

1. 上传转写文本。
2. 自动抽取面试官问题和用户回答。
3. 对关键回答逐题评分。
4. 生成完整复盘报告。
5. 将薄弱点写入长期记忆。

### 2.4 语音面试

后续可以增加：

1. 录音上传。
2. 语音转文字。
3. 实时模拟面试。
4. 语速、停顿、口头禅分析。
5. 语音反馈。

## 3. Agent 能力优化

### 3.1 引入 OpenAI Agents SDK 或 LangGraph

第一版先写轻量 Harness。

后续可以对比升级：

1. OpenAI Agents SDK：工具调用、handoff、tracing 更标准化。
2. LangGraph：状态机、人类确认、持久化工作流更适合复杂流程。

优化目标：

1. 更清晰的 Agent 调度。
2. 更好的运行追踪。
3. 更强的失败恢复。
4. 更容易展示系统设计能力。

### 3.2 RAG 与面经库

后续可以引入：

1. pgvector。
2. 面经向量检索。
3. 历史面试记录检索。
4. 用户项目经历检索。
5. 岗位知识库检索。

用途：

1. 根据相似 JD 找相似面经。
2. 根据薄弱点推荐复习材料。
3. 根据历史回答生成更精准追问。

### 3.3 更强的记忆系统

当前记忆先用 `memory_items`。

后续可以优化：

1. 记忆置信度衰减。
2. 用户确认后再写入长期记忆。
3. 合并重复记忆。
4. 区分短期弱点和长期弱点。
5. 生成个人能力画像。

### 3.4 自进化策略优化

后续可以增加：

1. 用户点赞、点踩。
2. 用户采纳建议记录。
3. Prompt A/B 测试。
4. Rubric 版本对比。
5. 训练前后得分趋势分析。

## 4. 评测与质量优化

### 4.1 自动评测集

后续可以准备：

1. 示例简历。
2. 示例 JD。
3. 示例面经。
4. 标准抽取结果。
5. 标准题库质量评价。
6. 示例回答和参考评分。

### 4.2 LLM-as-Judge

后续可以用独立评测模型评价：

1. 题目相关性。
2. 建议可执行性。
3. 是否编造用户经历。
4. 回答评分是否合理。
5. 报告是否个性化。

### 4.3 规则评测

适合自动检查：

1. 题目是否不少于 25 道。
2. 每个模块是否不少于 8 道。
3. 是否包含 `question_id`。
4. 是否包含评分锚点。
5. 是否包含 Markdown 报告九段结构。

## 5. 工程优化

### 5.1 异步任务

备战包生成可能耗时较长。

后续可以增加：

1. Celery。
2. RQ。
3. FastAPI BackgroundTasks。
4. 任务状态轮询。
5. 失败重试队列。

### 5.2 缓存

后续可以增加：

1. Redis 缓存解析结果。
2. 缓存相同文本 hash 的结构化解析。
3. 缓存报告导出结果。

### 5.3 文件存储升级

当前使用本地文件。

后续可以换成：

1. S3。
2. MinIO。
3. 阿里云 OSS。
4. 腾讯云 COS。

### 5.4 数据安全

后续可以增加：

1. 简历文本脱敏。
2. 邮箱、手机号自动遮蔽。
3. 文件加密存储。
4. 用户删除数据。
5. 数据导出。

### 5.5 部署

后续可以增加：

1. Dockerfile。
2. docker-compose。
3. GitHub Actions。
4. 云服务器部署。
5. 日志采集和监控。

## 6. 报告能力优化

### 6.1 PDF 导出

当前只做 Markdown。

后续可以增加：

1. Markdown 转 PDF。
2. 报告封面。
3. 目录。
4. 高亮重点。
5. 打印友好样式。

### 6.2 多版本对比

后续可以支持：

1. 简历 v1 和 v2 对比。
2. 同一 JD 下多次备战包对比。
3. 回答第一次和第二次评分对比。
4. 薄弱点变化趋势。

## 7. 简历展示亮点

后续如果做得更完整，简历可以突出：

1. 多 Agent 编排与 Harness 设计。
2. Pydantic 结构化输出校验。
3. PostgreSQL + JSONB 保存 Agent 结果。
4. Agent 运行日志与可观测性。
5. 记忆系统与个性化训练。
6. 自动评测与 Prompt 版本管理。
7. RAG 面经库和相似岗位检索。

## 8. 优先级建议

MVP 后建议按这个顺序优化：

1. Web 前端。
2. 自动评测集。
3. RAG 面经库。
4. 真实面试转写复盘。
5. 异步任务和缓存。
6. 登录注册和多用户。
7. PDF 导出。
8. OpenAI Agents SDK 或 LangGraph 重构。
