# Phase 2.4C Candidate Integration Risk Analysis

日期：2026-10-21。

| 风险 | 控制与验收 | 剩余限制 |
| --- | --- | --- |
| metadata 通过被误称整个候选或 Token 通过 | 文档 46 单独限定资格，保留 2.4B 原结论 | 后续仍须设计并完成 2.4D 门禁 |
| AI 盲评被误称人工 | 决策与报告均明确 evaluator=AI，引用原标识和报告哈希 | AI 评分局限不因工程检查消失 |
| 生产被误切换 | 独立类、版本必填、无环境变量开关；生产服务和原类文件哈希不变 | 后续显式修改生产路由需单独授权 |
| v1/v2 串用或注入失败被掩盖 | 具体 assembler 类型匹配、构造期异常终止、绑定和版本/资产检查 | 不试图防御有权限直接篡改 Python 进程内任意方法的调用者 |
| fallback 冒充 v2 成功 | 复用已有 fallback，并记录 metadata_applied=false 与实际版本 null | Candidate 的普通执行仍可能降级，必须排除出成功样本 |
| 增加 Provider 调用或改变请求 | 不改 Base/Draft/client；fake transport 比较完整请求、参数和调用数；冻结重放零调用 | 离线验证不证明真实 Provider 的延迟和 Token 效率 |
| metadata 基线漂移 | Reviewed assembler/rules 哈希与旧 replay 记录相等，构造及运行前后检查资产哈希 | 进程间环境/库升级仍需单独记录和验证 |
| 题目语义、ID/顺序或 API 改变 | 19 份语料、两版本、重复执行；完整冻结题库相等；Schema 和身份字段比较 | 冻结语料无法证明所有未来题目的语义质量 |
| 证据、技术栈、重复检查回退 | 使用原 assembler 及规则的字节版本；v2 引用校验、既有安全专项回归 | 有限规则库仍有未知自然语言边界 |
| degraded evaluation/长期记忆污染 | 不改这些路径，运行全量离线与既有降级/记忆安全测试 | 未模拟真实供应商响应分布 |
| 历史资产被覆盖 | 开工前 297 文件 SHA-256、读写 guard、输出新目录、已有输出拒绝覆盖、终检 | 哈希检查检测持久变化，读写 guard 覆盖验证器执行窗口 |

既有仓库存在大量未提交内容，本阶段采取新增文件方式，不清理或回滚原改动。迁移仅在临时 SQLite 执行，不修改应用数据库。
