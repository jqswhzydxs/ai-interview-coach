# 第一阶段 MVP Feature Spec v0.1

## 1. Feature 概述

本 feature spec 用于整理 AI Interview Coach Agent 第一阶段 MVP 的已确定功能范围。

来源文档：

1. `docs/01-prd-v0.2.md`
2. `docs/AI-Interview-Coach-Agent-PRD-v0.1.md`

整理原则：

1. 以 `01-prd-v0.2.md` 为准。
2. `AI-Interview-Coach-Agent-PRD-v0.1.md` 仅作为历史背景和补充来源。
3. 不新增 PRD 之外的功能。
4. 不重写业务愿景，只明确第一阶段 MVP 需要实现、验证和排除的功能边界。

## 2. 第一阶段 MVP 目标

第一阶段 MVP 需要完成一个可演示的求职准备闭环：

```text
输入简历 + 输入 JD + 可选输入面经
↓
生成简历-JD 差距分析
↓
生成岗位专属面试题库
↓
生成面试备战要点手册
↓
用户选择一道题并输入回答
↓
系统输出单题评分、问题分析、改进版回答和下一题建议
```

第一阶段优先服务后端开发岗位。

第一阶段核心工作流为：

1. 完整面试备战包生成。
2. 单题模拟回答评分。

面试转写文本或面试回忆可以作为可选输入和后续复盘材料，但第一阶段 MVP 的主线验收优先围绕上述两条核心工作流。

## 3. 目标用户

第一阶段面向两类用户：

1. 在校大学生：准备实习、校招、项目面试、考研复试中的技术面。
2. 社会求职者：准备后端开发跳槽、转岗、面试复盘。

用户通常已经具备以下材料或场景：

1. 有简历，但不确定是否匹配目标岗位。
2. 有目标岗位 JD，但不知道应重点准备哪些能力。
3. 可能有面经或历史面试记录，但不知道如何转化成训练题。
4. 需要对单题回答获得结构化评分和改进建议。

## 4. 输入范围

### 4.1 必需输入

1. 简历。
   - 支持 PDF。
   - 支持 DOCX。
   - 支持 Markdown。
   - 支持纯文本。
2. 目标岗位 JD。
   - 支持用户粘贴文本。
   - 支持用户粘贴 Markdown。

### 4.2 可选输入

1. 面经。
   - 由用户手动粘贴。
   - 可以来自网上相似岗位面经。
   - 可以来自用户自己的历史面试记录。
2. 面试录音转写后的文本。
   - 第一阶段不直接处理音频文件。
   - 仅处理用户已经转写好的文本。
3. 单题模拟回答。
   - 用户可以从系统生成的题库中选择一道题并提交回答。
   - 用户也可以手动输入一道题和自己的回答。

## 5. 功能范围

### 5.1 简历解析

系统应从简历中提取结构化信息：

1. 基本信息。
2. 教育背景。
3. 技术技能。
4. 项目经历。
5. 实习或工作经历。
6. 奖项、证书、论文、竞赛等补充信息。

验收标准：

1. 能从 PDF、DOCX、Markdown、纯文本简历中提取可用于后续分析的文本。
2. 能生成结构化简历画像。
3. 项目经历、技能关键词和工作经历不得凭空编造。

### 5.2 JD 解析

系统应从目标岗位 JD 中提取结构化信息：

1. 岗位名称。
2. 岗位职责。
3. 硬性要求。
4. 加分项。
5. 技术关键词。
6. 隐含能力要求，例如沟通、协作、工程规范、业务理解。

验收标准：

1. 能识别后端开发岗位相关技术栈和能力要求。
2. 能区分硬性要求与加分项。
3. 能将 JD 要求用于后续匹配分析和题库生成。

### 5.3 面经处理

面经不是必需输入，但系统应支持将用户手动粘贴的面经作为增强材料。

系统应从面经中提取：

1. 高频知识点。
2. 高频问题。
3. 面试官追问方向。
4. 与目标 JD 相关的部分。
5. 与用户简历项目相关的部分。

验收标准：

1. 没有面经时，系统仍能基于简历和 JD 生成备战包。
2. 有面经时，题库和备战建议应体现面经中的高频问题或追问方向。
3. 系统不得自动联网搜索面经。

### 5.4 简历-JD 差距分析

系统应基于简历和 JD 生成差距分析。

输出应包含：

1. 总体匹配度。
2. JD 核心要求拆解。
3. 简历中已经匹配的能力。
4. 简历中表达不足但可能具备的能力。
5. 简历中明显缺失的能力。
6. 后端开发岗位重点风险点。
7. 简历修改建议。
8. 面试重点准备方向。

验收标准：

1. 每条关键结论应尽量引用来源。
2. 来源可以来自简历、JD 或用户粘贴的面经。
3. 建议应具体到用户可以修改简历或准备回答。
4. 不输出空泛的通用评价。

### 5.5 岗位专属面试题库

系统应生成岗位专属面试题库。

题库要求：

1. 总题量不少于 25 道。
2. 分为 3 个模块。
3. 每个模块不少于 8 道。
4. 至少一个模块需要 9 道或以上。

三个模块：

1. 自我介绍定制题。
2. 后端岗位专业能力题。
3. 行为经历与项目深挖题。

每道题应包含：

1. 问题正文。
2. 考察目的或考察点。
3. 难度等级。
4. 来源依据：简历、JD、面经或综合推断。
5. JD 核心匹配关键词。
6. 高分回答框架。
7. 可直接套用的 STAR 结构模板。

额外约束：

1. 专业能力题必须紧扣 JD 核心职责，避免泛化。
2. 行为经历与项目深挖题需要附带 1 到 2 个连环追问。
3. 项目追问必须围绕用户简历中的真实项目展开。
4. 不得编造用户没有写过的经历。

### 5.6 面试备战要点手册

系统应基于简历、JD 和可选面经生成面试备战要点手册。

内容要求：

1. 回答加分点不少于 8 条。
2. 回答雷点不少于 6 条。
3. 面试注意事项覆盖 3 个维度：
   - 简历细节匹配。
   - 现场话术节奏。
   - 反问环节话术。

每条回答加分点应包含：

1. 推荐表达。
2. 对应的岗位匹配点。
3. 可数据化表达方式。
4. 可以落到简历或项目经历中的具体位置。

每条回答雷点应包含：

1. 禁忌表述。
2. 可能带来的负面印象。
3. 更好的替代表达。

验收标准：

1. 加分点和雷点应结合用户材料。
2. 建议应能直接指导用户准备面试回答。
3. 不输出与岗位无关的泛化建议。

### 5.7 完整面试备战包生成

完整面试备战包应按以下展示顺序组织：

1. 备战总览。
2. JD 核心要求拆解。
3. 简历-JD 差距分析。
4. 简历优化建议。
5. 面试准备优先级。
6. 岗位专属面试题库。
7. 面试备战要点手册。
8. 推荐先练的 3 道题。
9. 下一步行动清单。

组织原则：

1. 先给行动建议。
2. 再给判断依据。
3. 最后引导用户进入训练。

验收标准：

1. 备战包内容应覆盖差距分析、题库、备战手册和行动清单。
2. 推荐先练的 3 道题应来自题库，并能作为单题评分入口。
3. 报告应适合导出为 Markdown。

### 5.8 单题模拟回答评分

用户选择一道题并提交回答后，系统应生成单题评分报告。

评分采用 100 分制。

评分维度：

1. 相关性。
2. 技术准确性。
3. 项目具体性。
4. 结构性。
5. 表达力。
6. 风险控制。

评分报告应包含：

1. 总分。
2. 分项评分。
3. 表现好的地方。
4. 需要改进的地方。
5. 回答中的技术错误或表达风险。
6. 高分回答框架。
7. 改进版回答示例。
8. 可能的面试官追问。
9. 下一题练习建议。
10. 是否写入用户长期薄弱点。

验收标准：

1. 评分必须解释扣分原因。
2. 反馈应定位到具体缺失点、技术点或表达问题。
3. 改进版回答应尽量复用用户真实经历。
4. 不得为了生成高分回答而编造用户经历。
5. 下一题建议应围绕当前薄弱点继续训练。

### 5.9 用户记忆与薄弱点沉淀

系统应将练习和复盘中反复出现的薄弱点沉淀为用户长期记忆。

记忆内容可以包括：

1. 常见薄弱点。
2. 表现较好的能力。
3. 常投岗位方向。
4. 最近训练重点。

验收标准：

1. 单题评分结果可以提出记忆更新建议。
2. 记忆更新应服务下一轮题目推荐和训练建议。
3. 记忆内容应来自用户材料、回答或评分结果，不得凭空推断敏感信息。

### 5.10 面试转写文本复盘

当用户输入面试录音转写文本或面试回忆时，系统可以生成复盘报告。

复盘报告包含：

1. 面试问题列表。
2. 用户回答摘要。
3. 表现好的地方。
4. 需要改进的地方。
5. 技术知识短板。
6. 表达与沟通问题。
7. 简历风险点。
8. 下一轮准备计划。

验收标准：

1. 第一阶段只处理文本，不处理音频文件。
2. 复盘结论应引用用户提供的转写文本或面试回忆。
3. 复盘结果应能转化为下一轮训练建议。

## 6. 非功能范围

第一阶段明确不做：

1. 自动联网搜索面经。
2. 招聘网站爬虫。
3. 自动投递。
4. 语音实时面试。
5. 直接处理音频文件。
6. 支付。
7. 企业 HR 端。
8. 多人协作。
9. 登录注册。

说明：

1. 用户原始想法中涉及联网搜索真题，但第一阶段已收敛为用户手动粘贴面经。
2. 音频相关能力第一阶段只支持转写后的文本。

## 7. 用户场景与验收

### 7.1 场景一：生成完整面试备战包

前置条件：

1. 用户提供一份简历。
2. 用户提供一个后端开发岗位 JD。
3. 用户可选提供面经。

用户操作：

1. 上传或粘贴简历。
2. 粘贴 JD。
3. 可选粘贴面经。
4. 请求生成完整面试备战包。

系统结果：

1. 输出备战总览。
2. 输出 JD 核心要求拆解。
3. 输出简历-JD 差距分析。
4. 输出简历优化建议。
5. 输出面试准备优先级。
6. 输出不少于 25 道岗位专属题。
7. 输出面试备战要点手册。
8. 推荐先练的 3 道题。
9. 输出下一步行动清单。

验收标准：

1. 题库数量和模块数量满足要求。
2. 项目追问基于用户简历中的真实项目。
3. 分析结论尽量有来源依据。
4. 报告结构符合规定顺序。

### 7.2 场景二：提交单题回答并获得评分

前置条件：

1. 系统已生成题库，或用户手动输入一道题。
2. 用户输入自己的回答。

用户操作：

1. 选择一道题。
2. 输入回答。
3. 请求评分。

系统结果：

1. 输出总分和分项评分。
2. 解释表现好的地方。
3. 解释需要改进的地方。
4. 指出技术错误或表达风险。
5. 给出高分回答框架和改进版回答。
6. 给出可能追问和下一题建议。
7. 给出是否写入长期薄弱点的建议。

验收标准：

1. 评分维度完整。
2. 扣分原因具体。
3. 改进版回答不编造用户经历。
4. 下一题建议与薄弱点相关。

### 7.3 场景三：使用面试转写文本做复盘

前置条件：

1. 用户提供面试录音转写文本或面试回忆。

用户操作：

1. 粘贴转写文本或面试回忆。
2. 请求生成复盘报告。

系统结果：

1. 输出面试问题列表。
2. 输出用户回答摘要。
3. 输出表现好的地方和需要改进的地方。
4. 输出技术短板、表达问题和简历风险点。
5. 输出下一轮准备计划。

验收标准：

1. 系统只处理文本输入。
2. 复盘结论基于用户提供内容。
3. 复盘结果能转换为后续训练重点。

## 8. 成功指标

第一阶段可以跟踪以下指标：

1. 简历信息提取准确率。
2. JD 要求提取准确率。
3. 匹配分析证据覆盖率。
4. 面试题相关性评分。
5. 建议可执行性评分。
6. 用户采纳率。
7. 多轮训练提升率。
8. 回答评分一致性。
9. 反馈定位率。

## 9. 质量约束

### 9.1 个性化约束

输出必须基于用户简历、JD、面经或回答内容。

系统应避免：

1. 与用户材料无关的通用建议。
2. 与 JD 不匹配的泛化题库。
3. 编造用户项目经历、技术栈或成果数据。

### 9.2 证据约束

关键分析结论应尽量提供来源依据。

来源可以是：

1. 简历片段。
2. JD 条目。
3. 用户粘贴面经中的问题类型。
4. 用户回答中的具体表达。

### 9.3 可执行性约束

输出应帮助用户直接行动。

可执行性体现为：

1. 简历建议能指导用户修改描述。
2. 题库能直接用于练习。
3. 评分反馈能指导用户改写回答。
4. 下一题建议能延续当前薄弱点。

### 9.4 稳定性约束

同一份输入在相同配置下，多次生成结果不应出现明显相互矛盾的判断。

至少需要保证：

1. 结构化输出字段稳定。
2. 评分维度稳定。
3. 报告展示顺序稳定。
4. 核心结论与输入材料一致。

## 10. 边界与假设

1. 第一阶段岗位方向为后端开发。
2. Java、Python、Go 等语言方向由简历和 JD 动态识别。
3. 第一阶段不纳入自动联网搜索能力。
4. 第一阶段不直接处理音频文件。
5. 第一阶段不要求正式前端。
6. Markdown 报告导出属于第一阶段已确定方向。
7. 用户长期记忆用于后续训练建议，不用于自动修改用户简历。

## 11. 版本验收清单

第一阶段 MVP 完成时，应满足：

1. 支持简历和 JD 输入。
2. 支持可选面经输入。
3. 支持简历、JD 和面经结构化解析。
4. 支持生成简历-JD 差距分析。
5. 支持生成不少于 25 道岗位专属面试题。
6. 支持生成面试备战要点手册。
7. 支持生成完整面试备战包。
8. 支持推荐先练的 3 道题。
9. 支持用户提交单题回答。
10. 支持输出 100 分制单题评分报告。
11. 支持给出改进版回答和下一题建议。
12. 支持薄弱点记忆更新建议。
13. 支持 Markdown 报告导出。
14. 不包含第一阶段明确排除的功能。
