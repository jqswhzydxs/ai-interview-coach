# AI Interview Coach Agent PRD v0.2

## 1. 项目定位

AI Interview Coach Agent 是一个面向求职者的简历岗位匹配与面试备战 Agent 系统。

它不是一个泛聊天机器人，而是围绕“找到岗位 -> 分析差距 -> 准备面试 -> 模拟练习 -> 复盘表现 -> 继续改进”的求职闭环，帮助用户完成结构化求职准备。

第一版优先服务后端开发岗位，后续再扩展到前端、AI 应用、数据分析等方向。

## 2. 目标用户

第一阶段用户：

1. 在校大学生：准备实习、校招、项目面试、考研复试中的技术面。
2. 社会求职者：准备后端开发跳槽、转岗、面试复盘。

用户特点：

1. 有简历，但不知道是否匹配目标岗位。
2. 看得懂 JD 的字面要求，但不知道面试官会如何追问。
3. 可以找到一些面经，但不知道如何转化为自己的训练题。
4. 面试后只能凭感觉复盘，难以定位表达问题和知识短板。

## 3. 核心业务场景

### 3.1 岗位准备场景

用户看到一个后端开发岗位 JD，希望知道：

1. 自己的简历和 JD 差在哪里。
2. 哪些经历应该重点包装和准备。
3. 哪些技术点可能被问。
4. 面试前应该优先复习什么。

### 3.2 模拟面试场景

用户准备某个后端岗位，希望系统基于简历、JD、面经生成一套岗位专属面试题库，并提供每道题的高分回答框架。

### 3.3 单题模拟回答评分场景

用户从系统生成的题库中选择一道题，输入自己的回答，希望系统判断：

1. 回答是否切题。
2. 技术点是否准确。
3. 是否结合了简历项目细节。
4. 表达结构是否清晰。
5. 如何改成更高分的回答。

### 3.4 面试复盘场景

用户参加完面试后，将录音转写文本或面试回忆粘贴进系统，希望知道：

1. 哪些问题答得好。
2. 哪些问题答得差。
3. 哪些回答有风险。
4. 下一轮面试前应该补什么。

## 4. MVP 范围

### 4.1 MVP 目标

第一版先完成一个完整可演示闭环：

```text
输入简历 + 输入 JD + 可选输入面经
↓
生成简历-JD 差距分析
↓
生成岗位专属面试题库
↓
生成面试备战要点手册
↓
用户从题库中选择一道题并输入回答
↓
系统输出单题评分、问题分析、改进版回答和下一题建议
↓
可选：用户输入面试转写文本或面试回忆
↓
系统输出面试复盘报告和下一轮训练计划
```

第一版核心工作流有两条：

1. 完整面试备战包生成：从简历、JD、可选面经生成差距分析、题库和备战手册。
2. 单题模拟回答评分：用户选择一道题并提交回答，系统给出评分、反馈、改写和后续训练建议。

### 4.2 第一版优先岗位

后端开发岗位。

优先覆盖的后端能力维度：

1. 编程语言基础：Java、Python、Go 可按用户简历和 JD 动态识别。
2. Web 框架：Spring Boot、FastAPI、Django、Gin 等。
3. 数据库：MySQL、PostgreSQL、Redis、索引、事务、SQL 优化。
4. 计算机基础：网络、操作系统、并发、数据结构与算法。
5. 工程能力：接口设计、权限认证、日志、异常处理、测试、部署。
6. 系统设计：缓存、消息队列、限流、分布式、可观测性。
7. 项目表达：项目背景、个人职责、技术难点、方案权衡、结果数据。

### 4.3 支持输入

必需输入：

1. 简历：支持 PDF、DOCX、Markdown、纯文本。
2. 目标岗位 JD：支持用户粘贴文本或 Markdown。

可选输入：

1. 面经：由用户手动粘贴，来源可以是网上相似岗位面经或自己的历史面试记录。
2. 面试录音转写后的文本：第一版不直接处理音频文件，只处理已经转成文本的内容。
3. 单题模拟回答：用户从题库中选择一道题，或手动输入一道题和自己的回答。

### 4.4 第一版不做

为了控制复杂度，第一版不做：

1. 自动联网搜索面经。
2. 招聘网站爬虫。
3. 自动投递。
4. 语音实时面试。
5. 支付。
6. 企业 HR 端。
7. 多人协作。

说明：用户原始提示词中提到“在浏览器中搜索近几年的真题”。第一版为了可控和可评测，改为“基于用户手动粘贴的面经、简历和 JD 生成题库”。联网搜索可以作为后续版本能力。

## 5. 核心输出

### 5.0 完整面试备战包展示顺序

完整面试备战包面向用户展示时，应按照“先结论、再证据、再训练”的顺序组织，避免用户一打开就被大量题目淹没。

推荐展示顺序：

1. 备战总览：说明岗位匹配度、最主要差距、最优先准备事项。
2. JD 核心要求拆解：拆成后端技术栈、项目经验、工程能力、加分项。
3. 简历-JD 差距分析：展示匹配优势、缺失能力、表达不足、风险点，并提供证据。
4. 简历优化建议：说明哪些项目描述要改、哪些技术关键词要补、哪些表述容易被追问。
5. 面试准备优先级：给出 Top 5 准备重点，例如数据库、缓存、接口设计、项目难点表达。
6. 岗位专属面试题库：按自我介绍定制题、后端岗位专业能力题、行为经历与项目深挖题展示。
7. 面试备战要点手册：展示回答加分点、回答雷点、现场话术节奏、反问环节话术。
8. 推荐先练的 3 道题：从题库中挑出最值得立即练习的问题，作为单题模拟回答评分入口。
9. 下一步行动清单：告诉用户今天可以先做什么、接下来练什么、复习什么。

这个顺序的目标是让用户先知道“我该怎么办”，再看“为什么这样判断”，最后进入“怎么练”。

### 5.1 简历-JD 差距分析报告

报告需要包含：

1. 总体匹配度。
2. JD 核心要求拆解。
3. 简历中已经匹配的能力。
4. 简历中表达不足但可能具备的能力。
5. 简历中明显缺失的能力。
6. 后端开发岗位重点风险点。
7. 简历修改建议。
8. 面试重点准备方向。

每条结论都应尽量引用来源，例如：

1. 来自简历的哪段项目经历。
2. 来自 JD 的哪条要求。
3. 来自用户粘贴面经的哪类高频问题。

### 5.2 岗位专属面试题库

系统需要一次性生成一套面试题库。

题库要求：

1. 总题量不少于 25 道。
2. 分为 3 个模块。
3. 每个模块不少于 8 道。
4. 至少一个模块需要 9 道或以上，以满足总题量不少于 25 道。

三个模块：

1. 自我介绍定制题。
2. 后端岗位专业能力题。
3. 行为经历与项目深挖题。

每道题需要包含：

1. 问题正文。
2. 考察目的。
3. 难度等级。
4. 来源依据：简历、JD、面经或综合推断。
5. JD 核心匹配关键词。
6. 高分回答框架。
7. 可直接套用的 STAR 结构模板。

额外要求：

1. 专业能力题必须紧扣 JD 核心职责，避免泛化。
2. 行为经历与项目深挖题需要附带 1 到 2 个连环追问。
3. 项目追问必须围绕用户简历中的真实项目展开，不能编造用户没有写过的经历。

### 5.3 面试备战要点手册

手册需要基于用户简历、JD 和可选面经生成。

内容要求：

1. 回答加分点不少于 8 条。
2. 回答雷点不少于 6 条。
3. 面试注意事项覆盖 3 个维度：
   - 简历细节匹配。
   - 现场话术节奏。
   - 反问环节话术。

每条回答加分点需要包含：

1. 推荐表达。
2. 对应的岗位匹配点。
3. 可数据化表达方式。
4. 可以落到简历或项目经历中的具体位置。

每条回答雷点需要包含：

1. 禁忌表述。
2. 可能带来的负面印象。
3. 更好的替代表达。

### 5.4 单题模拟回答评分报告

当用户从题库中选择一道题并输入回答后，系统需要生成单题评分报告。

评分报告包含：

1. 总分：建议采用 100 分制。
2. 分项评分：相关性、准确性、结构性、具体性、表达力、风险控制。
3. 表现好的地方。
4. 需要改进的地方。
5. 回答中的技术错误或表达风险。
6. 高分回答框架。
7. 改进版回答示例。
8. 可能的面试官追问。
9. 下一题练习建议。
10. 是否写入用户长期薄弱点。

### 5.5 面试表现复盘报告

当用户输入面试录音转写文本或自己的面试回忆后，系统需要生成复盘报告。

复盘报告包含：

1. 面试问题列表。
2. 用户回答摘要。
3. 表现好的地方。
4. 需要改进的地方。
5. 技术知识短板。
6. 表达与沟通问题。
7. 简历风险点。
8. 下一轮准备计划。

## 6. 如何判断输出有用

“有用”需要拆成可观察指标，而不是只靠感觉。

### 6.1 简历分析有用

满足以下条件越多，说明越有用：

1. 每条建议都能对应到简历或 JD 的具体内容。
2. 用户能直接根据建议修改简历。
3. 建议能指出“该补什么细节”，而不是只说“表达不够具体”。
4. 修改后，系统重新分析时匹配度提升。

### 6.2 题库生成有用

满足以下条件越多，说明越有用：

1. 题目明显围绕后端岗位，而不是通用面试题。
2. 专业题能对应 JD 的核心职责。
3. 项目题能对应用户简历里的真实项目。
4. 行为题有连续追问，接近真实面试压力。
5. 每道题都有高分回答框架，而不是只有题目列表。

### 6.3 单题评分有用

满足以下条件越多，说明越有用：

1. 评分能解释扣分原因，而不是只给分数。
2. 反馈能指出回答中的具体问题句子或缺失点。
3. 改进版回答能复用用户真实经历，而不是编造经历。
4. 下一题建议能围绕当前薄弱点继续训练。
5. 用户再次回答同类问题时得分提升。

### 6.4 面试复盘有用

满足以下条件越多，说明越有用：

1. 系统能指出用户回答中的具体问题句子或表达。
2. 系统能识别重复出现的薄弱点。
3. 系统能把复盘结果转化成下一轮训练题。
4. 用户下一次回答同类问题时得分提升。

### 6.5 可量化指标

第一版可以跟踪：

1. 信息抽取准确率：简历、JD、面经关键点是否抽取正确。
2. 题目相关性评分：题目是否与简历、JD、面经相关。
3. 证据覆盖率：分析结论是否有来源依据。
4. 建议可执行性评分：用户是否能照着修改。
5. 用户采纳率：用户是否采纳系统建议。
6. 多轮训练提升率：同类问题多次练习后得分是否提升。
7. 评分一致性：同一回答在相同 Rubric 下多次评分是否稳定。
8. 反馈定位率：反馈是否能定位到具体句子、技术点或表达问题。

## 7. 当前版本验收标准

v0.2 需求阶段的验收标准：

1. 已明确目标用户和第一版岗位方向。
2. 已明确输入格式和不做自动联网搜索。
3. 已明确核心输出为差距分析、题库、备战手册、单题评分报告和复盘报告。
4. 已明确模拟面试题库的数量、模块、字段和质量要求。
5. 已明确第一版同时做完整面试备战包生成和单题模拟回答评分。
6. 已明确如何从用户反馈和训练得分判断输出是否有用。

## 8. 下一步待确认

后续还需要继续确认：

1. 后端岗位第一版是否偏 Java 后端、Python 后端，还是根据简历和 JD 自动识别。
2. “笔试准备”是否进入 MVP，还是先只做面试准备。
3. 面试复盘第一版做到什么深度：只总结薄弱点，还是逐题拆解整段转写文本。
4. 是否需要输出可下载 Markdown / PDF 报告。
5. 是否需要保留多份简历版本与多份 JD 的历史记录。
