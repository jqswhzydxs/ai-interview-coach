# 模拟面试生成规格 v0.1

## 1. 目标

本规格用于定义“岗位专属面试题库”和“面试备战要点手册”的生成标准。

它是对原始提示词的产品化改造。第一版不要求系统自动浏览器搜索，而是基于用户提供的简历、目标岗位 JD、手动粘贴的面经和历史面试记录生成内容。

生成出的题库不仅用于阅读，也要作为单题模拟回答评分的输入。因此每道题需要有稳定的题目编号、来源依据和评分锚点，方便后续 Answer Evaluator Agent 进行评分。

## 2. 输入

必需输入：

1. 用户简历：PDF、DOCX、Markdown 或纯文本。
2. 目标岗位 JD：用户粘贴的岗位描述。

可选输入：

1. 用户手动粘贴的相似岗位面经。
2. 用户自己的历史面试记录。
3. 用户面试录音转写后的文本。
4. 用户长期记忆：历史薄弱点、常投岗位、历史训练得分。

## 3. 输出一：岗位专属面试题库

完整面试备战包最终展示时，不应直接从题库开始，而应先给用户结论和准备优先级。推荐最终报告顺序为：

1. 备战总览。
2. JD 核心要求拆解。
3. 简历-JD 差距分析。
4. 简历优化建议。
5. 面试准备优先级。
6. 岗位专属面试题库。
7. 面试备战要点手册。
8. 推荐先练的 3 道题。
9. 下一步行动清单。

其中“岗位专属面试题库”和“面试备战要点手册”是完整备战包的核心主体，“推荐先练的 3 道题”是进入单题模拟回答评分的入口。

### 3.1 总体要求

题库需要满足：

1. 总题量不少于 25 道。
2. 分为 3 个模块。
3. 每个模块题量不少于 8 道。
4. 题目必须围绕后端开发岗位。
5. 题目必须结合简历、JD 或用户提供的面经。
6. 不允许出现大量通用泛化题。

### 3.2 模块一：自我介绍定制题

目标：

帮助用户准备不同面试开场场景下的自我介绍和简历主线表达。

题目方向：

1. 1 分钟自我介绍。
2. 3 分钟项目导向自我介绍。
3. 针对 JD 的自我介绍。
4. 针对实习生或校招生身份的自我介绍。
5. 针对转岗或社招身份的自我介绍。
6. 面试官追问“你为什么适合这个岗位”。
7. 面试官追问“你的项目和我们岗位有什么关系”。
8. 面试官追问“你最大的技术优势是什么”。

每道题需要给出：

1. 回答主线。
2. JD 匹配关键词。
3. 可复用表达句式。
4. STAR 或“背景-能力-证据-匹配”结构模板。

### 3.3 模块二：后端岗位专业能力题

目标：

围绕 JD 核心职责和后端开发能力生成技术题。

题目方向按简历和 JD 动态选择：

1. 编程语言基础。
2. Web 框架。
3. 数据库与 SQL。
4. Redis 与缓存。
5. 消息队列。
6. 网络与 HTTP。
7. 并发与线程安全。
8. 系统设计。
9. API 设计与鉴权。
10. 日志、监控、异常处理。
11. 测试与部署。

要求：

1. 专业能力题必须紧扣 JD 核心职责。
2. 如果 JD 明确提到某项技术，该技术必须进入题库。
3. 如果简历中出现某项技术但 JD 未提到，可以作为项目追问或加分项。
4. 不能只问“你了解 Redis 吗”这类泛题，应改为场景化问题。

示例：

```text
不合格：你了解 MySQL 索引吗？

合格：你的项目中如果课程查询接口数据量从 1 万增长到 100 万，你会如何设计 MySQL 索引？如何判断索引是否生效？
```

### 3.4 模块三：行为经历与项目深挖题

目标：

还原真实面试中围绕简历项目连续追问的场景。

题目方向：

1. 项目背景。
2. 个人职责。
3. 技术选型。
4. 难点解决。
5. 性能优化。
6. 数据库设计。
7. 接口设计。
8. 团队协作。
9. 失败经历。
10. 项目复盘。

每道题必须附加 1 到 2 个连环追问。

示例：

```text
主问题：你简历中提到实现了课程问答功能，请详细讲一下这个功能的整体链路。

追问 1：如果用户问题没有命中知识库，你的系统会如何处理？
追问 2：你怎么评估回答质量，如何避免模型胡乱回答？
```

## 4. 每道题的标准字段

每道题都应包含：

1. 题目编号：question_id，需要在一次题库生成结果中唯一。
2. 所属模块。
3. 问题正文。
4. 考察目的。
5. 难度等级：基础、中等、困难。
6. 来源依据：简历、JD、面经、综合推断。
7. JD 核心匹配关键词。
8. 高分回答框架。
9. STAR 结构模板。
10. 追问问题：仅行为经历与项目深挖题必需。
11. 备考建议。
12. 评分锚点：回答这道题时必须覆盖的关键点，用于单题评分。

## 5. 输出二：面试备战要点手册

### 5.1 回答加分点

不少于 8 条。

每条包含：

1. 加分点标题。
2. 推荐表达方式。
3. 对应 JD 匹配细节。
4. 数据化表述技巧。
5. 可落到简历中的项目或经历。

示例：

```text
加分点：用数据说明项目效果

推荐表达：我负责接口性能优化，将某接口平均响应时间从约 800ms 降到 300ms 左右。

岗位匹配：体现后端性能优化和问题定位能力。

数据化技巧：使用响应时间、QPS、错误率、数据量、并发数等指标。
```

### 5.2 回答雷点

不少于 6 条。

每条包含：

1. 雷点标题。
2. 禁忌表述。
3. 负面印象。
4. 替代表达。

示例：

```text
雷点：把团队成果说成个人独立完成

禁忌表述：这个系统都是我一个人做的。

负面印象：可能被认为夸大经历，后续追问容易暴露细节不足。

替代表达：我主要负责接口设计和数据库表设计，其他模块由团队成员协作完成。
```

### 5.3 面试注意事项

必须覆盖三个维度。

维度一：简历细节匹配

1. 简历中每个技术关键词都要能讲清楚使用场景。
2. 项目里的个人职责必须明确。
3. 不熟悉的技术不要放在核心技能位置。

维度二：现场话术节奏

1. 先回答结论，再补充细节。
2. 技术题不要上来背概念，要结合场景解释。
3. 不会的问题先说理解，再说思路，不要直接沉默。

维度三：反问环节话术

1. 可以问团队技术栈和业务方向。
2. 可以问岗位入职后的主要工作。
3. 可以问新人培养和代码评审流程。
4. 避免一上来只问薪资、加班和福利。

## 6. 生成原则

系统生成内容必须遵守：

1. 先依据 JD，再结合简历，最后参考面经。
2. 不编造用户没有写过的项目经历。
3. 不把用户粘贴的面经说成确定真题。
4. 如果材料不足，需要标注“基于综合推断”。
5. 题目要有面试真实感，避免模板化。
6. 专业能力题要后端岗位导向，不能泛泛问 AI、前端或产品问题。
7. 高分回答框架要能直接指导用户组织回答。

## 7. 推荐提示词模板

```text
你是一个资深后端开发面试官和求职教练。

你的任务是基于用户提供的简历、目标岗位 JD，以及可选的手动粘贴面经，生成两份面试备战成品：

第一份：岗位专属面试题库
第二份：面试备战要点手册

重要限制：
1. 不要联网搜索。
2. 不要编造用户没有写过的项目经历。
3. 不要把用户提供的面经说成确定真题，只能作为参考材料。
4. 如果某个题目不是直接来自简历、JD 或面经，需要标注为“综合推断”。
5. 专业能力题必须紧扣目标岗位 JD 的核心职责，避免通用泛化题。

输入材料：
【简历】
{{resume_text}}

【目标岗位 JD】
{{jd_text}}

【可选面经】
{{interview_experience_text}}

【可选用户历史薄弱点】
{{user_memory}}

输出要求：

请按以下顺序组织最终报告：
1. 备战总览。
2. JD 核心要求拆解。
3. 简历-JD 差距分析。
4. 简历优化建议。
5. 面试准备优先级。
6. 岗位专属面试题库。
7. 面试备战要点手册。
8. 推荐先练的 3 道题。
9. 下一步行动清单。

一、岗位专属面试题库
1. 总题量不少于 25 道。
2. 分为三个模块：自我介绍定制题、后端岗位专业能力题、行为经历与项目深挖题。
3. 每个模块不少于 8 道题。
4. 每道题必须包含：question_id、问题正文、考察目的、难度、来源依据、JD 核心匹配关键词、高分回答框架、STAR 结构模板、备考建议、评分锚点。
5. 行为经历与项目深挖题每题必须附带 1 到 2 个连环追问。

二、面试备战要点手册
1. 基于用户简历中的个人经历生成。
2. 回答加分点不少于 8 条，每条说明岗位匹配细节表达和数据化表述技巧。
3. 回答雷点不少于 6 条，每条说明禁忌表述、负面印象和替代表达。
4. 面试注意事项必须覆盖：简历细节匹配、现场话术节奏、反问环节话术。

输出风格：
1. 具体、可执行。
2. 像真实面试官会问的问题。
3. 对后端开发岗位有针对性。
4. 不要输出空泛鼓励。
```

## 8. 质量验收标准

生成结果需要通过以下检查：

1. 题目总数不少于 25。
2. 三个模块每个不少于 8 题。
3. 专业能力题 80% 以上能对应 JD 职责或技术关键词。
4. 项目深挖题 100% 能对应简历中的真实项目或经历。
5. 每道题都有来源依据。
6. 回答加分点不少于 8 条。
7. 回答雷点不少于 6 条。
8. 不出现自动联网搜索结果。
9. 不编造用户经历。
10. 最终报告必须按“备战总览 -> JD 拆解 -> 差距分析 -> 简历建议 -> 准备优先级 -> 题库 -> 手册 -> 先练 3 题 -> 行动清单”的顺序组织。
